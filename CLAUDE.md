# Beat the Ghost - Roblox dev workspace

- Roblox Studio is the source of truth (no Rojo). Cloud sessions reach Studio through `roblox-mcp-bridge/` (Lenny starts it on his PC), either with the `Roblox_Studio` MCP tools or with `tools/studio.py` / `tools/deploy_luau.py`, which call the same bridge from the shell. How to write code: see "How to work" below.
- `game/` is a read-only mirror of the place's scripts, exported with `python3 tools/export_studio.py` (`--list`, `--studio "<name>"`). Never edit files in `game/` itself; edit a copy (see "How to work"), push it to Studio, then `tools/save_game.sh` re-exports.
- Save tokens: use `graphify query/path/explain` (rules below) to find code, then read only the needed lines (`script_read` with a line range in Studio, or `game/` files with offset/limit). Don't dump whole scripts.
- Roblox API reference offline: `/opt/creator-docs/content/en-us/reference/engine/` (classes/*.yaml, enums, datatypes); Luau docs in `/opt/creator-docs/content/en-us/luau/`.

## Images (icons, UI art) — no emoji

- The user dislikes emoji in UI: use generated image icons instead.
- One command makes an image and returns its Roblox id: `python3 tools/make_image.py <name> "<what it is>"` (`--kind art --size 1024x576` for backgrounds/art; `--no-upload` to look at it first). It uses Pollinations' free model, cuts the white background for icons, stores the PNG in the public `game-art` repo and uploads it through Studio. The last printed line is `rbxassetid://...`.
- Needs the `game-art` repo at `/home/user/game-art` with push access: if missing, attach `lennygihub/game-art` (add_repo, push) and clone it there. Needs the bridge's "Image relay" window running on the PC.
- Look at the image (Read the PNG) before using it in the game; regenerate with another `--seed` if it's off. Never put text in generated images; add text with TextLabels.
- This game's pictures use `--style ps2` (low-poly PS2 horror look; the default style is a bright cartoon). `--kind art` keeps the dark background (good for shop cards); `--upload-only` pushes + uploads a PNG that is already saved.
- The lobby shop's pictures are a batch: `tools/art/shop_images.txt` (name | size | prompt) with `python3 tools/art/gen_shop_images.py gen [names] [--seed N]` (generate, no upload; review with a contact sheet), `upload` (ids into `tools/art/shop_ids.json`; don't start/stop a playtest while it runs) and `module <path>/ReplicatedStorage/Shared/ShopArt.luau` (writes the id table the shop reads). Don't write "PlayStation", "console" or "no game controller" in a prompt: the model then draws controllers and logos.

## 3D models: hand-built blocky PS2 parts only

- **Never use Roblox's AI for anything in this game** (the user, 2026-11-18: "do it yourself or subagents"): not the Assistant's generation, not `generate_mesh`, `generate_scene`, `generate_texture` or any other AI generator. Running your own Luau through the bridge is fine (that is only code execution).
- **Never use `generate_mesh` (Studio's AI mesh generator), `generate_scene`, `generate_texture` or any other AI 3D generator for this game.** The user rejected them for good (2026-11-17, the lobby props): they come out smooth and cartoonish with a painted texture, not in the game's blocky PS2 look. Don't offer it again.
- Every prop is **hand-built from plain Parts** (boxes, cylinders, wedges) in an Edit-mode build script under `tools/build/` (see `tools/build/lobby_detail.luau`: fountain, gates, wagon, well, graves, scarecrows, pumpkins): chunky shapes, few parts, flat dark colours, the `PS2_*` MaterialVariants (`PS2_Stone`, `PS2_DarkBeam`, `PS2_Siding`, `PS2_FloorPlanks`, `PS2_Mud`...), Neon only for small lights. Same look as the log cabins and the hand-built trees.
- A free Creator Store model only if it is already blocky / low-poly in that style, and only after showing the user; after inserting, list every Script/LocalScript/ModuleScript inside it and delete them unless the model needs them and you've read them.
- Check the result with a screenshot (needs the Studio window visible on the PC; a black image means it's minimized). Put props in named Folders/Models, anchor them, set `CanCollide/CanQuery/CanTouch` false on decoration.
- In the lobby, keep particle effects tiny: a big or dense smoke emitter on a path greys out the whole screen of a player standing in it.

## Saving the game's code (user's standing instruction)

## How to work (user's choice: this replaces the old "always delegate to subagents" rule)

The user wants **the main conversation writes the game code itself**, as whole coherent modules, and tests it in Studio. Subagents are the exception, not the default.

1. **Check Studio first**: `python3 tools/studio.py state` (or the MCP `list_roblox_studios` + `get_studio_state`). If the bridge is off, tell the user and stop. The tunnel sometimes drops single requests (HTTP 502 "upstream request failed"): the tools retry those by themselves; only a 502 that lasts a minute or more means the bridge is really off. The tunnel is a Microsoft dev tunnel since 2026-11 (address in `tools/export_studio.py`, set up on the PC with `roblox-mcp-bridge/setup-devtunnel.bat`); it replaced ngrok, whose free plan stopped after 1 GB a month (`403 ERR_NGROK_725`). Its free allowance is not published, so keep screenshots few (each is ~0.7 MB through the tunnel; freeze the moment and take one, or one contact sheet's worth). A 401 means the environment has no bridge key for the tunnel's address (the user adds it: network secret, header Authorization). If it is off and the work can be written without Studio, commit the changed files to `pending/src/` on `main` (same layout as `game/`, syntax-checked with `tools/deploy_luau.py --root pending/src --check`), with a note in `pending/README.md`. The PC's "GitHub sync" window (`roblox-mcp-bridge/pull-from-github.js`, started by `start-bridge.bat`) writes them into the open Studio by itself, no tunnel needed; it is one way, so say plainly that nothing was playtested. While `pending/src/` exists, the current code is `game/` with `pending/src/` copied over it: start the work copy from that. When the bridge is back: `tools/save_game.sh`, then delete `pending/`.
2. **Make a work copy** of the code in your scratchpad: `cp -r game <scratchpad>/src` (same layout as `game/`; `git fetch origin main` first so `game/` is current). Edit there with Read/Edit/Write. Write new features as complete ModuleScripts (one job each, `--!strict`) rather than many tiny MCP edits.
3. **Check and push**: `python3 tools/deploy_luau.py --root <scratchpad>/src <changed files>`. It syntax-checks every file with `luau-compile` and pushes nothing if one fails. Studio must be in Edit mode (`tools/studio.py stop`).
4. **Test it for real in a playtest**: `tools/studio.py play`, wait ~10 s, then drive the game with `tools/studio.py luau Client <file>` scripts that call the game's own remotes (e.g. hit a ghost, collect a drop, buy an upgrade) and return numbers to check. Then take `tools/studio.py shot <png>` screenshots and Read them, read `tools/studio.py console` for errors, and `stop`. Look at every visual change; fix what looks wrong and test again.
   - A `luau` call runs in its own VM (its own copy of ModuleScripts). To steer the running client (camera, open a panel, time of day), add Studio-only attribute hooks in the client (`if RunService:IsStudio()`) and set those attributes from the test script.
   - Keep each `luau` call under ~30 s of waiting; split long scenarios into several calls.
5. **Save**: `tools/save_game.sh "game: <summary>"` at the end of the request (see above), and remind the user to save the place in Studio.

**Subagents** (`.claude/agents/`): use one only for a separate, parallel chore that would flood this conversation, e.g. generating a batch of icons with `tools/make_image.py` or searching audio, run in the background with a precise brief (read `.claude/roblox-rules.md`, don't edit Studio, write results to a file, report in a few lines). Never hand the main game code to a subagent.

**Keep the user posted**: a short line before each big step (what you're building, what a test showed), and screenshots of results. Be honest about what was tested and what wasn't.

## graphify (only when it saves tokens)

The graph maps **only this game's own Luau scripts** in `game/` (exported from Studio). No docs, no tooling, nothing from other games. It starts empty (`graphify-out/graph.json` with 0 nodes) and fills on the first `tools/save_game.sh`, which exports Studio's scripts to `game/` and rebuilds the graph offline (AST only, no LLM: `GRAPHIFY_BACKEND=none graphify update .`). `graphify-out/.graphify_build.json` (`gitignore: false, code_only: true`) lets graphify read `game/` even though `.gitignore` lists it; keep that file. Never run the `/graphify` LLM/semantic extraction: it costs tokens.

While the graph is empty or small, just grep `game/` or use Studio search. Once it has real code, use it only when it is cheaper than the alternative:
- Use `graphify query "<question>"` (capped at ~1000 tokens), `graphify path "<A>" "<B>"` or `graphify explain "<X>"` when you don't know where something lives, or when the answer spans several files or scripts over ~150 lines. Then read only the lines it points to.
- Skip it when you already know the file and lines, the file is small (< ~150 lines), or a single exact `grep -n` will find it.
- Don't read `graphify-out/GRAPH_REPORT.md` or `graph.json` directly (large); only for a full architecture review.
